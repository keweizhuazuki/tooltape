# ToolTape 离线查看器

[English](README.md) | 简体中文

### 使用方式

直接在现代浏览器中打开 [`index.html`](index.html)，无需服务器、构建、安装依赖、CDN 或账号。页面只读取你选择或拖入的本地文件，不上传、不发送网络请求，也不写入浏览器存储。内容安全策略会阻止外部资源、网络连接、表单提交和嵌入对象。

1. 点击 **Open tape** 选择本地 `.tape` 文件，也可以将一个文件拖入页面。
2. 在时间线中选择一次调用，查看输入、输出或记录的异常类名。
3. 搜索工具名或输入/输出内容，勾选 **Errors only** 只看异常；按 **Esc** 清除筛选。
4. 点击 **Compare tape** 加载第二份记录。页面会显示首次分歧的位置；点击 **Inspect divergence** 可定位并查看两份记录的具体内容。

**Try an example** 仍在内存中加载与 `fixtures/weather-retry.tape` 一致的旧版 v1 示例：第一次天气查询抛出 I/O 异常，第二次重试成功。示例不会执行真实工具调用，也不会读取远程文件。

### 记录信息

紧凑的信息栏展示格式版本、记录完整性、来源标识和缩短的采集策略 SHA-256 标识。悬停在策略标识上可查看完整值，无障碍标签也包含完整值。元数据由记录方自行声明，不代表来源已经过认证。

- **SESSION CLOSED**：v2 存在最终 `END` 行，且计数与实际调用数一致。它仅说明记录会话已关闭，不能证明业务成功；存在异常或零次调用的会话也可以正常关闭。
- **INCOMPLETE**：v2 的元数据和已有调用行有效，但缺少 `END`。可以检查现有内容，页面明确警告不能用于安全回放。
- **LEGACY · UNKNOWN**：v1 没有元数据和结束标记，无法验证采集策略或记录完整性。内置示例保持 v1。

比较区单独展示第二份记录的格式、完整性、来源和策略。即使所有已记录调用一致，不同策略标识仍会触发警告；旧版记录的策略覆盖范围会标记为无法验证。

### Unicode 与转义文本搜索

搜索可直接匹配 JSON 键和字符串值中的 Unicode 字符，包括 `😀` 等 emoji，即使查看面板仍显示规范化的代理项转义。原有规范 JSON 文本匹配也保留，因此仍可搜索 JSON 转义写法和精确数字文本。这是子串筛选，不是 JSON 值相等查询。

额外搜索视图只解码**一次**字符串转义。若字段实际保存的是字面字符 `\ud83d\ude00`，不会再次把它转换成 emoji；搜索该转义写法则仍可能匹配 emoji 的规范表示或字面文本。与原来一样，搜索使用 JavaScript 不依赖地区的 `toLowerCase()` 并移除查询首尾空白；不新增 Unicode 规范化、去重音、地区特定匹配或模糊匹配。例如，组合字符 `é` 与 `e` 加组合重音仍是不同序列。

解码视图仅临时生成，在转小写前的 UTF-16 长度不超过规范源文本，不保存为逐调用搜索索引。原有 16 MiB / 50,000 条输入限制继续适用；这不是浏览器堆内存或延迟保证。显示方式、规范序列化、精确数字及比较语义保持不变；搜索不会修改或脱敏录制值。

### 键盘操作

- Tab 可抵达可见的 Open tape / Compare tape 按钮，不会停在不可见文件输入上；Enter 或空格打开浏览器原生文件选择器。
- 激活 Previous page 或 Next page 后切换页面，焦点移至该页第一条调用，右侧查看的选中项保持不变。到达边界时对应按钮禁用；没有第二页时隐藏分页控件。
- Esc 清除活动筛选时优先显示焦点调用所在页，否则显示选中调用所在页；筛选控件保留焦点。若原焦点分页按钮变为不可用，焦点回到可见调用。没有活动筛选时，Esc 不改变页面、焦点或选中项。
- 激活 Clear comparison 后，焦点返回 Compare tape，同时保留主记录选中项并提示比较已清除。

这些是经配置的桌面/移动模拟浏览器项目验证的特定键盘行为，不代表完整无障碍审计或读屏软件兼容认证。

### 文字对比度

辅助小字由 `#65716e` 调整为 `#87948f`。在选中调用背景上的计算对比度约从 3.04:1 提升至 4.89:1，普通面板约从 3.56:1 提升至 5.72:1；保留深色视觉层级、正文与状态颜色。

浏览器以真实计算样式及透明度合成，检查部分标签、预览、占位文字、页脚和调用的默认/悬停/选中/键盘焦点状态。按 [W3C 最低对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，这些小字样本要求至少 4.5:1，不通过四舍五入放宽阈值。[实际测量记录](../docs/contrast-results.json)包含来源提交和运行信息，桌面/移动 Chromium 样本的最低比值为 4.89479:1。

这是当前深色主题的定向文字检查，不等于完整 WCAG 审计。字体可读性、非文字控件、强制颜色模式、真机及辅助技术仍需独立评审。

### 格式与限制

- 文件使用不带 BOM 的 UTF-8 编码，采用 LF 换行，最后一行必须以 LF 结束；不接受 CRLF。
- 第一行是 `TOOLTAPE`、一个制表符和 `1` 或 `2`。v1 后面直接是调用行。
- v2 第二行必须是 `META`、一个制表符，以及无填充 base64url 编码的规范 JSON 元数据，准确包含两个字符串字段：`{"policyId":"sha256:<64 位小写十六进制>","source":"static.identifier"}`。键顺序如示例，不含多余空白；缺失、未知或重复字段会被拒绝。
- `source` 必须符合 `[A-Za-z0-9_.:-]{1,128}`，只应用静态来源标签，不应包含人名、本地路径、凭据或其他敏感信息。
- v2 的最后一行可为 `END`、一个制表符和规范非负十进制调用数，必须与实际调用数一致。前导零、计数不符、重复结束行或结束行后的任何内容都会被拒绝。缺少 `END` 可供检查，但会明确标记为不完整；未以 LF 结束的残缺行仍会被拒绝。
- v1/v2 的调用行格式相同，包含六个由制表符分隔的字段：从零开始的连续序号、非负纳秒耗时、工具名、输入、状态以及输出/异常类名。
- 工具名、输入和输出使用无填充的 base64url 编码。Base64 只是编码，不是加密。
- 工具名必须符合 `[A-Za-z0-9_.:-]{1,128}`，只能使用静态标识符。状态为 `OK` 或 `ERROR`；异常类名支持以点分隔的 Unicode 标识符，最长 1,024 个 UTF-16 单元，排除控制及格式字符。
- 输入和成功输出必须是 JSON 对象；对象内部可以包含数组或其他 JSON 值。重复键、超过 64 层的嵌套、无效 UTF-8、无效或非规范 base64url、非连续序号和其他格式错误都会被拒绝。
- 文件最大 16 MiB，最多 50,000 次调用。时间线每页最多渲染 250 条匹配记录，通过 Previous page / Next page 替换当前页；页脚显示从 1 开始的可见范围及匹配总数。跳转到靠后的分歧时直接显示所在页，不渲染此前所有页面。翻页保留右侧选中项，即使该调用位于其他页。单个超大内容面板只显示前 100,000 个字符，并明确提示；搜索和比较仍使用完整内容。
- 原始 JSON、规范 JSON 和所有调用的规范内容分别限制为 16 MiB UTF-8；数字文本及展开后十进制最长 10,000 字符，每份 JSON 最多 100,000 个值节点。填充数字前预检容量，防止小体积指数文件造成无限内存膨胀。
- 无效的新文件不会覆盖之前已加载的有效记录。打开新的主记录会清除旧的比较结果。

完整定义见 [v1/v2 格式说明](../docs/FORMAT.md)。

### 比较规则与精度

按记录顺序比较调用序号、工具名、规范化输入、状态和规范化输出/异常类名。首次内容变化或缺失/多余的调用就是首次分歧。界面中的位置从 1 开始，记录序号仍从 0 开始。

调用内容比较忽略耗时、元数据和会话关闭状态，但策略差异与不完整警告会单独显示。对 JSON 对象键排序，并无损规范化十进制数。因此 `1.0` 与 `1` 相等，键顺序不同的等价对象也相等；数组顺序有意义。超出 JavaScript 安全整数范围的数值仍保持精确，耗时求和使用 `BigInt`。显示的总耗时是各次工具调用耗时之和，不代表整个流程的墙钟时间。

比较只覆盖实际记录的字段，无法判断已脱敏或省略字段是否相同。相同记录不代表所有业务行为都相同；有效的 `END` 只能证明记录会话已关闭，不能证明业务流程成功。

### 隐私与安全

查看器不会自动脱敏，记录中仍可能包含敏感参数或结果，请谨慎检查和分享。加载的数据仅保存在当前标签页内存中，关闭或刷新页面即可丢弃。来自记录的内容使用 `textContent` 显示，不会被解释为 HTML、脚本或可点击链接。浏览器扩展和操作系统不在本页面的控制范围内。

### 可复现验证

开发测试需要 **Node.js 18 或更高版本**，无需安装任何包。在仓库根目录运行：

```sh
node viewer/test-core.cjs
node viewer/test-interactions.cjs
```

第一个脚本检查 v1/v2 解析、严格元数据校验、结束计数与位置、不完整或空会话、50,000 次调用边界、与实际示例的一致性、数字规范化、大整数精度、错误编码、比较逻辑和无网络/存储调用。第二个脚本使用简化的内存 DOM 模型检查完整性和来源展示、策略差异警告、文件读取、筛选、首次分歧、缺失调用、异常提示、被中断或过期的异步读取、大小限制和安全文本展示。

这些检查不等同于真实浏览器渲染或无障碍测试。[真实浏览器验证说明](browser-tests/README.md) 提供离线 Chromium/Firefox/WebKit 交互、响应式布局与基准/差异/移动端截图的复现步骤。[浏览器 CI 工作流](../.github/workflows/browser.yml) 使用固定版本的开发依赖，直接从磁盘打开 HTML，并上传包含源文件和样例来源信息的真实截图。[真实五项目 CI](https://github.com/keweizhuazuki/tooltape/actions/runs/38067175946)已通过 188 项测试（跳过 2 项移动端重复截图），包含 50,000 条录制末尾分歧导航；选用的真实 Chromium 桌面和移动截图也已检查；Unicode 搜索截图来自本次运行；其余已发布截图的来源文件分别记录了对应的准确运行。
